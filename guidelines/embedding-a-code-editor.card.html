Embedding a code editor

Textarea declines code-editor chrome as a mode, and the reasoning has not changed: line numbers, syntax highlighting, bracket matching, tab capture and an undo stack that survives them are an editor, not a form control. A Textarea that grew half of them would be a worse editor than any real one and a worse textarea than it is now.

What kept this item open was the other half of the sentence. The guidance said “embed a real editor and give it this control’s chrome” — and nothing in the system said what that chrome was. So here it is, as a rule you can copy.

The chrome

.editor-surface {
  display: flex;
  font-family: var(--font-mono);
  font-size: var(--text-sm);
  line-height: var(--leading-normal);
  color: var(--input-text);
  background: var(--input-background);
  border: var(--border-width) solid var(--input-border);
  border-radius: var(--input-radius);
  overflow: hidden;
  transition: var(--transition-control);
}
.editor-surface:focus-within {
  border-color: var(--input-border-focus);
  box-shadow: var(--focus-ring);
}

Those are the same tokens Textarea reads, so an embedded CodeMirror or Monaco sits in a form beside real controls without looking pasted in. :focus-within is the important line: the editor owns focus internally, so the surface has to respond to focus landing anywhere inside it — this is the one place the control's focus ring cannot come from the focused element itself.

What the system still owns

  • The label, hint and error. Wrap the editor in Field exactly as you would a Textarea — it supplies the label, the described-by wiring and the error message, none of which an editor library provides.
  • The disabled and read-only look. Swap to --input-background-disabled and --input-text-disabled, and set the editor's own read-only flag — a greyed surface with a live cursor is the worst of both.
  • The height. Give the surface a max-height and let the editor scroll inside it. An editor that grows without limit pushes the form's submit button off the screen.

What it does not

  • Keyboard behaviour inside the editor is the library's. Do not re-bind Tab, Escape or Enter from outside: Tab in a code editor indents, and a form that steals it makes the editor unusable. If the editor traps Tab, give the user a documented way out (Escape then Tab is the common contract) and say so in the field's hint.
  • Announcements. A code editor is not a textarea to a screen reader, whatever ARIA it claims. Do not paper over it — say what the field is in its label ("Routing rule, code editor").

Still use Textarea mono for anything that is merely monospaced — a key, a serial, a short expression, a log paste. The moment a field wants line numbers is the moment it stopped being a form field.
