Why primitives have no specs

Box, Surface, Container, Stack, Grid (+ GridItem), Spacer, Divider, AspectRatio, Image, Text, Heading — twelve exports, no .spec.html between them, and that is the settled position rather than a backlog. Every other component in the system has a fourteen-section spec because it has judgment attached: when to reach for it, what it must not be used for, how its copy should read. A primitive has none of that, and writing the document anyway would produce twelve files whose honest answer to most sections is "not applicable".

The decision: primitives are documented by their .d.ts (the full prop surface), their .prompt.md (purpose, do/don't, one example), the two specimen cards in components/primitives/, and Token Architecture.md — which is their real contract, because a primitive's props are the token scales. A primitive earns a spec only if it acquires judgment: semantics, states, keyboard behaviour, or a rule about when not to use it. None currently has any. Components are the opposite default — one is not frozen until its spec exists.

Nine of fourteen are not applicable, and of the five that survive, four are already written somewhere better. What is genuinely missing is not twelve specs but one page of anti-patterns — so that is what the rest of this card is.

The primitive anti-patterns

The two that matter

  • Margins instead of gaps. Box still accepts m / mx / my / mt / mr / mb / ml; as of 1.13.0 they warn. Element margins collapse unpredictably and they break the moment a sibling is reordered or deleted — which is exactly what layout tooling does. Space siblings with the parent's gap.
  • A primitive where a component exists. A Surface with a hairline and a padded footer is a Card; a Box with a border and a focus ring is an Input. The rebuild loses the states, the ARIA and the density wiring, and it drifts from the real component the first time that component changes.

Also don't

  • Raw values in token props. p="14px", background="#f4f6f8". The props take token names; literals bypass density and the dark scope.
  • Reaching past the semantic tier. background="grey-100" instead of "surface-sunken" — forbidden by the token contract, and now warned.
  • A Spacer between every pair of items. That is gap. Spacer is for the one gap a gap cannot express — usually grow, pushing a trailing action to the edge.
  • A Spacer as a section break. That is a Divider or a heading; a Spacer is aria-hidden and means nothing.
  • Nesting Box for one property. Four wrappers to centre something is a flex parent that was not written.
  • Text or Heading with a hand-set fontSize. Use the scale; style is an escape hatch, not the API.

What replaced the specs

  • Validation, in the one place every primitive passes through. scale.js now warns once per bad name for colour family, radius, elevation, border tone and text size. A mistyped token is the primitive layer's characteristic bug and it fails silently — var(--text-secondry) is valid CSS that resolves to nothing, so the property is dropped and the value inherits. Invisible in review, nearly invisible on screen.
  • A deprecation with a reason, not a removal. Margin props stay because the console kit still uses a few; they warn because accepting them silently keeps teaching the pattern the system's own layout rule forbids.
  • This card. The anti-patterns and the policy, in one place, instead of twelve documents repeating that a Box has no keyboard behaviour.

When this decision should be revisited: if a primitive gains a state, a role, focus behaviour, or a genuine "use this instead" rule against another primitive, it has acquired judgment and it needs a spec. Surface interactive is the closest — one hover tint and a pointer cursor — and is worth watching: if it ever grows focus, keyboard activation or a pressed state, it has become a Card or a Button and should be one.
