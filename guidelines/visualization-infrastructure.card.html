Governance · Architecture Standard

Shared Visualization Infrastructure

The Meridian data visualization layer rests on ten shared infrastructure systems. Rather than having individual charts (Bar, Line, Area, Scatter, Heatmap, Donut, Timeline) independently reinvent coordinate math, scale mapping, tick intervals, legend swatches, keyboard traversal, and accessible table fallbacks, these ten systems are specified once as common infrastructure and consumed across all chart implementations.

The Ten Infrastructure Systems

Every chart in this design system is an assembly of these shared systems, configured for a specific analytical geometry:

Global Accessibility & WCAG Baseline

  • Programmatic Name & Description: Every visualization container must have a programmatically available accessible name (via aria-label or aria-labelledby) and, where complex, a concise structural description in an SVG <desc> element detailing chart type, domain range, and high-level trend.
  • Multi-Channel Redundancy: Exact or essential information cannot exist exclusively in color, hover state, geometry, animation, or spatial proximity. Categorical colors are paired with SVG hatching patterns or point glyphs.
  • Accessible Marks & Focus: Interactive marks carry role="graphics-symbol", accessible labels, visible keyboard focus rings (2px offset, --focus-ring), and roving tabindex navigation.
  • Contrast Ratios: Text labels meet WCAG 1.4.3 (≥ 4.5:1 against surfaces); essential graphical elements (bars, lines, baselines, reference limits) meet WCAG 1.4.11 (≥ 3:1).
  • Non-Dragging Alternatives (WCAG 2.2 2.5.7): Dragging-based brushing, interval selection, or pan operations must provide non-dragging equivalents (step buttons, range sliders, or numeric input bounds).
  • Minimum Target Sizes (WCAG 2.2 2.5.8): Pointer targets for discrete data points must provide at least 24×24px hit bounds (recommended 44×44px touch targets).
  • Accessible Data Table Fallback: Dense visualizations must expose an alternate structured HTML <table> with programmatic header-to-cell relationships (scope="col", scope="row") toggleable via Alt+F11 or a visible action button.
  • Two-Dimensional Reflow (WCAG 1.4.10): At high zoom (up to 400%), visualization-specific spatial content (maps, multi-axis matrices, heatmaps) is explicitly recognized under WCAG as content where two-dimensional scrolling is permitted to preserve spatial meaning.

Detailed System Specifications

10 Common Infrastructure Blocks
01

Plot Region

Canvas & Bounds

The Plot Region establishes the geometric bounding box, margin reservations, coordinate mapping functions, and layer stacking ladder for rendering visual elements.

  • Margin Allocation: Top/Right/Bottom/Left margins reserve space for axis tick labels, titles, and legends to prevent label clipping across container resizes.
  • 6-Level Stacking Hierarchy:
    1. Layer 0: Background Canvas & Surface Fill
    2. Layer 1: Gridlines & Shaded Threshold Tolerance Bands
    3. Layer 2: Series Marks, Bar Fills, Area Shapes & Paths
    4. Layer 3: Reference Baselines, Targets & Control Limits (UCL/LCL)
    5. Layer 4: Data Annotations, Callouts & Active Hover Crosshairs
    6. Layer 5: Tooltip Inspection Cards & Popover Flyouts (z-index: 20+)
02

Scale Engine

Mathematical Mapping

The Scale Engine transforms raw domain values into output visual channels (X/Y coordinates, bar lengths, circle radii, angles, opacities). All scales are mathematical functions provided by viz-core.js.

  • Categorical / Band Scale: Maps discrete categories to evenly spaced bands with configurable inner/outer padding.
  • Linear Scale: Maps continuous numerical domains to Cartesian lengths with zero-baseline preservation options.
  • Logarithmic Scale: Maps wide-dynamic-range quantitative values (e.g. vibration frequencies 10Hz to 100,000Hz) using logarithmic power steps.
  • Temporal Scale: Maps ISO 8601 timestamps to linear time ranges in Indian Standard Time (IST).
  • Sequential & Diverging Scales: Maps quantitative metrics to continuous color ramps or multi-hue diverging ramps around a center threshold.
  • Area (Sqrt) Scale: Calculates bubble/circle radius using square-root scaling (r = √(value)) to ensure visual circle area remains proportional to magnitude.

Linear Radius (Anti-pattern)

Doubling the value doubles the radius, causing a 400% increase in perceived circle area. Falsifies data.

Square-Root Radius (Standard)

Radius scales by square root of value so circle surface area directly represents proportional quantity.

03

Axis

Scale Explanation

An Axis is not a chart. Its sole job is to explain a positional scale to human readers through ticks, gridlines, labels, and units of measure.

  • Nice Tick Generation: Calculates human-readable tick intervals based on powers of 10, 2, and 5 (e.g., 0, 20, 40, 60, 80, 100).
  • Label Formatting: Consistently formats currency (₹2,50,000 in en-IN), percentages (84.2%), and units (ppm, °C, mm/s).
  • Responsive Tick Decimation: When container width shrinks, ticks thin by an integer factor (every 2nd or 3rd tick) while preserving the zero baseline and peak values.
04

Legend

Encoding Guide

A Legend documents non-positional visual encodings. It maps colors, stroke dashes, and symbols to data series or value thresholds.

  • Categorical Swatches: Renders series color chips alongside series names and non-color symbols. Clicking a swatch toggles series isolation (dimming non-selected series to 0.25 opacity).
  • Continuous Gradient Ramps: Renders horizontal or vertical color bars with min/mid/max values for heatmaps and choropleth matrices.
  • Keyboard Accessibility: Legend buttons are focusable via Tab, support Enter/Space activation, and announce selection states via aria-pressed.
05

Label

Direct Identification

The Label system directly identifies marks, bar tips, endpoints, and data slices without forcing users to hover.

  • Collision Strategy: When labels overlap, the system executes an automated hierarchy: (1) stagger vertically/horizontally, (2) thin non-critical labels, (3) fallback to endpoint-only labels.
  • Contrast Integrity: Direct labels placed inside colored marks automatically adjust text color (white on dark series, primary ink on light series) to guarantee 4.5:1 contrast.
06

Annotation

Contextual Callout

Annotations add explanatory text, callout pins, or highlighted range banners tied to specific data coordinates (e.g. *“Die Change at 11:30 IST”* or *“Tool Room Maintenance Window”*).

  • Spatial Anchoring: Anchors to data coordinates rather than absolute pixel coordinates, ensuring annotations track correctly across responsive resizing.
  • Non-Visual Exposure: Annotations are programmatically associated with target data marks via aria-describedby, ensuring screen readers announce the annotation when the mark is focused.
07

Reference Indicator

Benchmarks & Limits

Reference Indicators represent baselines, static targets, historical averages, Upper/Lower Control Limits (UCL/LCL), and shaded tolerance bands.

  • Semantic Status Lines: Reference lines carry explicit semantic tones (danger for ceiling breaches, success for targets, neutral for baselines) with 1.5px dashed strokes.
  • Tolerance Bands: Shaded rectangular zones (--status-critical-soft, --status-warning-soft) spanning value ranges on Layer 1 behind visual marks.
  • Labelled Intent: Every reference line must render an explicit text label (e.g., *“Max Permissible Vibration: 4.5 mm/s”*); lines with unexplained numbers are forbidden.
08

Color Encoding

Palette & Hatching

The Color Encoding system standardizes categorical, sequential, diverging, and status hues while guaranteeing accessibility in monochrome environments.

  • Categorical Series: Strict adherence to the 6-step categorical series --viz-1 through --viz-6. Series beyond 6 categories must be grouped into an "Other" bucket or transformed to a Table.
  • Multi-Channel Pattern Hatching: Every categorical hue is paired with a distinct SVG pattern preset (diagonal stripes, stippled dots, crosshatch, horizontal bars, diamond mesh).
  • Color-Vision Deficiency Verification: Tested and verified against Deuteranopia, Protanopia, and Tritanopia.
09

Data Interaction

Inspection vs Operation

Data Interaction separates read-only inspection (hover/focus data readouts) from transactional operations (selection, filtering, brushing, drill-down).

  • Inspection vs Operation: Hovering or focusing a point reveals inspection data via Tooltip; clicking or pressing Enter/Space selects or filters. Essential data is never hidden solely behind hover.
  • Keyboard Roving Tabindex: The chart container is a single Tab stop. Arrow keys (←/→/↑/↓) navigate marks sequentially; Home/End jump to boundaries; Esc dismisses inspection.
  • Non-Dragging Alternatives (WCAG 2.2): Brushing or range zooming affordances must provide companion step buttons, range sliders, or numeric input bounds.
  • Minimum Target Hit-Area: Discrete data points implement an invisible expanded hit bounding box (minimum 24×24px, 44×44px for touch).
10

Visualization State

Lifecycle & Telemetry

The Visualization State system standardizes asynchronous and operational lifecycle conditions across all chart types.

  • Loading Skeleton: Employs mer-skeleton-sweep animation with proportional placeholder bars/lines while applying aria-busy="true".
  • Empty State vs Numeric Zero: Explicitly distinguishes an empty dataset (missing telemetry records) from a valid numeric reading of 0 (e.g. zero downtime hours). Empty states display an icon and message without drawing misleading zero-value marks.
  • Degraded / Partial Stream: When telemetry feeds drop packets, missing intervals render as broken dashed paths with a warning badge, preventing false linear interpolation through machine downtime.
  • Error & Retry: Network or parser failures present an in-situ recovery banner with a retry action button.
