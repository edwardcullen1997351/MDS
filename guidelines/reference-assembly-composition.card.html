Reference Assembly Composition Standard

When assembling enterprise reference screens from Meridian design tokens and layout templates, teams must never write bespoke control CSS. Missing interaction patterns must be promoted into Tier 1 primitives or Tier 2 composites to guarantee 100% token purity, zero horizontal overflow, and zero accessibility violations.

The Prime Directive of Reference Assemblies: The Zero-Bespoke-CSS Mandate

Never write custom control styles in an assembly story. If an assembly requires a new grouping (e.g. aligning a date stepper next to a view toggle) or a new control (e.g. a segmented switcher), that is a genuine Tier 1 or Tier 2 Design System gap. Solve it once in the system packages so all enterprise applications inherit the certified behavior.

The 70-Point Verification Matrix

Every reference assembly must pass 100% of these 5 gates evaluated across 14 enterprise scenarios and 5 canonical viewports (320px, 390px, 768px, 1440px, 1920px) = 70 verification points:

GateRequirementAutomated Check
Gate 1: Zero-Bespoke-CSS Zero control/toolbar overrides; 100% token purity Source AST check for raw hex, !important, and bespoke classes
Gate 2: Viewport Containment WCAG 2.2 Reflow (1.4.10): scrollWidth <= clientWidth CDP layout evaluation at 320px, 390px, 768px, 1440px, 1920px
Gate 3: Automated Accessibility 0 Axe violations; Text contrast >= 4.5:1; Active state >= 3:1 Axe-core run across all 14 scenarios and 5 viewports
Gate 4: Tri-Pane State Sync Left selector filters Center; Center updates Right; Keyboard navigation Automated ETag 409 conflict, multi-plant scope switch, and J/K shortcuts
