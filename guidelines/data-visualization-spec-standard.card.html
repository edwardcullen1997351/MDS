Data Visualization System specification standard

A Data Visualization System is an architectural and graphical framework for encoding quantitative, temporal, categorical, and relational data into communicative visual structures — bar charts, line graphs, sparklines, area charts, donut charts, scatter matrices, heatmaps, gauges, and multi-metric analytics canvases. It owns visual mark encoding, scale mapping, color series assignment, threshold limits, interactive crosshairs, accessible data alternatives, and dense numerical typography. Its specification documents visualization-specific contracts only — establishing strict visual integrity, accessibility compliance, and cognitive legibility without duplicating atomic controls. This page fixes the fourteen sections a Data Visualization specification contains, their order and stable numbering, and what each section must answer.

How to apply it

  • All fourteen sections are defined; numbers are stable identifiers. Like Core Components, Layout Templates, and Navigation Systems, sections §01 through §14 appear in exact ascending order. A cross-reference such as §07 Keyboard or §08 Accessibility retains the exact same meaning across all system specifications and is never renumbered.
  • Visual integrity and truthfulness over decoration. Data visualization is an analytical tool, not illustration. Every mark, axis, tick, threshold, and hue must convey verifiable data. Zero-baselines on magnitude charts, proportional geometry, unclipped scales, and non-distorting aspect ratios are mandatory system rules.
  • Color is never the sole information carrier. Every visualization must satisfy multi-channel encoding (patterns, stroke styles, point glyphs, direct labels) and meet WCAG 1.4.11 (minimum 3:1 graphical contrast) and WCAG 1.4.3 (minimum 4.5:1 text/label contrast). Colors strictly adhere to the six-step categorical series --viz-1 through --viz-6 and designated semantic status tokens.
  • Equivalence of accessible data representation. Every graphic must provide an equivalent programmatic representation — an accessible DOM data table fallback, descriptive chart summaries (<desc> / aria-roledescription="chart"), live region updates, and keyboard focus traversal across discrete data points.
  • Real manufacturing ERP scenarios. All reference metrics, examples, scales, and labels reflect the fixed plant setting: Suryodaya Autocomp Ltd — Chakan plant (PL-04), Pune — real industrial KPIs: Overall Equipment Effectiveness (OEE), CNC spindle vibration (mm/s), furnace annealing temperatures (°C), press shop scrap rates, rejection PPM, Shift A/B/C output, rupees formatted in en-IN (₹2,50,000, ₹1.5L).

What every data visualization specification ships

A Data Visualization specification carries a status stamp in its masthead (status: frozen <date> · N open items) and is accompanied by a functional reference implementation:

  • 1 · The specification. specs/data-viz/<Visualization>.spec.html — sections §01–§14 in order, documenting the visual encodings, scale algorithms, geometry tables, palette assignments, keyboard traversal rules, and accessibility requirements.
  • 2 · Live reference implementation. Interactive working chart built with real system tokens and rendering primitives (SVG/Canvas), wired to realistic plant data at full volume (e.g. 24-hour machine telemetry, 30-day rejection trends, multi-line shift comparisons).
  • 3 · Do/Don't visual pairs. Placed directly inside the sections whose rules they demonstrate (e.g. §01 Purpose, §06 States, §08 Accessibility, §10 Content rules, §12 Anti-patterns) with concise analytical rationale.

The fourteen

All present, in ascending order, in every Data Visualization System specification
§01

Purpose

Always

Defines the analytical question the visualization answers, the cognitive task it supports (comparison, trend/time-series, part-to-whole, distribution, correlation, deviation, or target tracking), the data shape it requires, and when an alternative visualization or tabular format must be chosen instead.

Must answer

Which analytical task it solves; required data dimensionality (single metric, continuous time series, multi-category distribution); minimum and maximum data points supported; chart selection routing table ("You want to analyze... / Use this chart / Instead of... / Why"); and when NOT to visualize (e.g. fewer than 3 data points where a KPI Stat or DescriptionList is clearer).

Shape

Prose, analytical category badge (Trend, Comparison, Distribution, Composition, Flow), dimensionality table, and a comparison table.

Do

"Use a Line Chart with continuous time scale to show 24-hour CNC spindle vibration trends and detect anomalous spike patterns."

Don't

"Use a Line Chart to compare static rejection counts across 4 discrete plant workshops." Discrete categories without continuous sequence require a Bar Chart.

§02

Anatomy

Always

Defines all structural zones, graphical marks, coordinate grids, guide elements, legends, tooltips, and background containers that compose the visualization.

Must answer

All structural regions: Chart Container / Frame, Plot Area (data canvas), X/Y Quantitative and Categorical Axes, Axis Baseline, Major/Minor Gridlines, Tick Marks & Labels, Series Marks (bars, paths/lines, area fills, scatter dots, arcs/wedges), Reference Lines (targets, means, specification limits), Threshold Bands (upper/lower control limits, tolerance zones), Data Callout Annotations, Legend Container & Swatches, Crosshair Cursor & Hover Line, Floating Data Tooltip, and Hidden Accessible Data Table container.

Shape

Diagram or numbered structural callouts over a live chart instance, followed by an Anatomy Slot table detailing part name, role, visual element type (SVG element / Canvas layer), and token assignments.

§03

Properties

Always

Defines the public configuration API, data contract schema, scale parameters, dimension mappings, formatting accessors, and interaction callbacks exposed by the visualization component.

Must answer

Data schema contract (array of data objects with typed keys), scale definitions (linear, time, band, log, ordinal), domain bounds ([min, max] or auto-padding), dimension accessors (xKey, yKey, seriesKey), visual channel encodings (color, stroke style, point shape), reference line configurations (threshold value, label, semantic tone), legend placement, tooltip formatters, and event handlers (onPointHover, onSeriesSelect, onBrushZoom). Explicitly documents refused properties (e.g. 3D perspective tilts, arbitrary raw hex color injections that bypass design tokens, unstructured arbitrary HTML strings in tooltips).

Shape

TypeScript prop interface, data item schema table, and dedicated refusal notes explaining why excluded capabilities are withheld to protect visual truth.

§04

Variants

Always

Defines the standardized analytical sub-types and visual layout modes supported by the chart abstraction, with explicit use-case rules for each.

Must answer

Standardized structural variants: for Bar Charts (Clustered, Stacked, 100% Normalized, Horizontal, Diverging); for Line Charts (Standard Multi-Series, Stepped/Step-After, Area-Filled, Sparkline / Micro-Trend); for Donut/Gauge Charts (Full Donut, Semi-Circle Gauge, Threshold Arc). Clarifies what constitutes a legitimate analytical variant versus an invalid decorative variant.

Shape

Variant comparison table detailing layout characteristics, cognitive workload, maximum supported series count, and live preview rows for each variant.

§05

Sizes

Always

Defines standard aspect ratios, container sizing classes, geometric stroke thicknesses, marker dimensions, margin budgets, and label spacing rhythms across densities.

Must answer

Standard rendering heights and aspect ratios (sparkline: 64×24px, compact-card: 280×160px / 16:9, standard-card: 440×260px, analytical-full: 800×420px / 2:1); margin allocations (top/right/bottom/left padding for axis tick labels); line stroke widths (1.5px background series, 2px primary series, 3px focused/active series); point radii (3px rest, 5px hover, 6px selected); bar corner radii (--radius-xs on outer caps, square at baseline); and density behavior under compact, comfortable, and expanded.

Shape

Geometry dimension table using semantic tokens (--viz-stroke-*, --space-*, --radius-*), container size matrix, and margin reservation guide.

§06

States

Always

Defines visual states for individual data marks, series, whole-chart containers, interactive crosshairs, and data thresholds, with token mappings and contrast ratios.

Must answer

Graphic element states: rest / default, hover / pointer-tracking, selected / pinned, dimmed / de-emphasized (unselected series reduced to opacity: 0.25 during series isolate mode), out-of-spec / breach (highlighted with --status-critical-solid when exceeding control limits); Whole-chart states: initial loading / skeleton shimmer, empty / zero data (distinguishing zero numeric value from missing null records), partial / degraded feed, and data error / fetch failed. Minimum 3:1 graphical contrast against chart background and 4.5:1 for data labels.

Shape

State transition matrix, opacity token assignments, and live renderings of all mark states and container states with contrast verification.

Do

"Render missing data as a broken dashed line with explicit 'No Telemetry' badge in tooltip, distinguishing it from a genuine 0.00 mm/s vibration reading."

Don't

"Drop null data points to the Y=0 baseline or interpolate through missing periods without visual break." That falsifies machine downtime as active zero-vibration operation.

§07

Keyboard

Always

Defines keyboard navigation patterns, focus management, mark-to-mark traversal, shortcut keys, and tabular view toggling across chart data points.

Must answer

Single Tab-stop entry to the chart container; spatial and sequential mark traversal (Arrow Left / Right to move between chronological data points along the X-axis, Arrow Up / Down to switch between active series in multi-line/stacked charts); Enter / Space to pin active tooltip or trigger drill-down route; Home / End to jump directly to first or last data point; Esc to dismiss pinned tooltip or clear series isolation; and global shortcut (Alt + F11 or focusable action button) to immediately swap between graphical chart view and accessible tabular data grid view.

Shape

Key-to-action table, roving tabindex architecture within SVG/DOM elements, and focus ring geometry specifications (2px offset ring, --focus-ring).

§08

Accessibility

Always

Defines the accessibility contract: WAI-ARIA graphics module semantics, non-color-only encoding channels, color blindness safe palettes, screen reader summaries, and WCAG compliance.

Must answer

WAI-ARIA landmark & semantics (role="region" aria-label="Line 2 Press OEE Trend Chart", container role="graphics-document" aria-roledescription="line chart", child marks role="graphics-symbol" aria-label="Shift B: 84.2% OEE at 14:00 IST"); high-level chart summary in <desc> element (stating chart type, axes, time range, min/max values, and overall trend); multi-channel encoding requirements (combining categorical hues --viz-1..--viz-6 with distinct dashed stroke patterns and point glyphs: circle, square, triangle, diamond); color blindness verification (tested against Protanopia, Deuteranopia, Tritanopia); and live region announcements on live data stream refresh (WCAG 1.1.1, 1.3.1, 1.4.1, 1.4.3, 1.4.11, 4.1.2, 4.1.3).

Shape

WCAG compliance table with rule references, complete SVG ARIA markup example, color blindness simulation checks, and screen reader output transcript.

Do

"Pair color hues with distinct point shapes (circles for Shift A, diamonds for Shift B) and dashed lines for secondary series to ensure legibility in monochrome."

Don't

"Distinguish four adjacent lines using four solid stroke colors alone with identical 2px solid lines." In monochrome or color vision deficiency, the lines cannot be distinguished.

§09

Motion

Always

Defines data transition choreography, path interpolation, bar expansion easing, hover crosshair tracking, and reduced-motion fallbacks.

Must answer

Initial entry animation duration (e.g. 250ms cubic-bezier(0.2,0,0,1) for progressive path drawing or bar height growth); data update / filter transition interpolation (180ms ease-out smoothly morphing points and lines to new Y coordinates without jumping); hover crosshair glide; tooltip position smoothing; and mandatory prefers-reduced-motion: reduce behavior (instantaneous render with 0ms transition duration, no progressive drawing, immediate crosshair snaps).

Shape

Motion specification table listing Animation Type, Duration Token, Timing Function, Interpolation Rule, and Reduced Motion override.

§10

Content rules

Always

Defines numerical formatting standards, Indian currency representation, units of measure, date/time formatting in IST, axis label truncation, and tooltip copy hierarchy.

Must answer

Numeric formatting rules (always use en-IN locale for Indian Rupees: ₹2,50,000; compact unit formatting: ₹1.2L / ₹4.5Cr; percentages formatted with one decimal 87.4%; PPM formatted as integer 140 ppm; temperature °C; vibration mm/s); date/time formatting (ISO YYYY-MM-DD, 24-hour time 14:30 IST, Shift identifiers: Shift A (06:00–14:00 IST)); Axis label formatting (max 12 characters per tick before abbreviation, never vertical 90° text; use 45° angle or decimation); Tooltip content hierarchy (Header: Dimension/Timestamp, Body: Metric name + Formatted value with units, Footer: Benchmark / Variance delta +3.2% vs Target); and zero/null messaging copy.

Shape

Number and currency formatting table, string truncation constraint table, and tooltip layout copy anatomy diagram using real shop-floor metrics.

§11

Responsive

Always

Defines how the visualization adapts across container widths and device viewports, including axis tick decimation, label rotation, legend wrapping, and touch tooltips.

Must answer

Desktop (≥1024px: full axis tick resolution, side-by-side legends, floating hover tooltips), Tablet (768px–1023px: tick decimation by factor of 2, horizontal legend wrapped below plot, 45° angled date labels), Mobile (<768px: tick decimation to start/middle/end points only, hidden non-essential gridlines, touch-driven scrubbing crosshair with fixed bottom data bar or modal sheet instead of floating tooltip), touch target minimums (44×44px hit-area per data point), and container-query-driven micro-chart fallbacks (e.g. converting full chart into sparkline + stat pill in narrow card widgets <240px).

Shape

Breakpoint adaptation matrix with container threshold triggers, layout restructure rules, and mobile viewport preview diagram.

§12

Anti-patterns

Always

Identifies visual chart misuses, mathematical misrepresentations, misleading scale distortions, and cognitive anti-patterns that falsify data or confuse operators.

Must answer

Explicit visualization anti-patterns: truncating the Y-axis baseline above zero on bar charts (exaggerating minor variances); utilizing 3D perspective charts (distorting volume and angle perception); dual non-zero Y-axes with unsynchronized scales (falsely implying correlation); using pie/donut charts for more than 5 categories or with slices <5%; using arbitrary non-token rainbow palettes; animating charts continuously on a loop (creating cognitive distraction); unlabelled axis units; omitting accessible data tables.

Shape

Do / Don't two-column guidance with realistic manufacturing plant consequence callout (e.g. truncated axis on scrap rate making a normal 0.2% variance look like a catastrophic line failure, causing false line stoppage).

Do

"Always start the Y-axis at zero (0%) for Bar and Area magnitude charts to preserve accurate proportional visual weight."

Don't

"Truncate the Y-axis baseline to 80% on a scrap rate bar chart to make a 2% variation fill the full vertical height." That misleads plant leadership on true defect proportion.

§13

Implementation notes

Always

Defines rendering engine decisions (SVG vs Canvas vs WebGL), scale algorithms, coordinate systems, label collision detection, z-index layering, and design tokens consumed.

Must answer

Rendering threshold guideline (SVG for <1,000 data points with accessible DOM elements; Canvas for 1,000–50,000 continuous time-series telemetry; WebGL for dense heatmaps); scale calculation and rounding algorithms; label collision avoidance logic (hiding overlapping labels, automatic tick thinning); layer stacking order (Background < Gridlines < Reference Bands < Series Marks < Target Reference Lines < Active Crosshair < Pinned Marks < Tooltip); event throttling (16ms requestAnimationFrame for pointer tracking); and complete token consumption inventory.

Shape

Layer stacking hierarchy diagram, rendering selection decision matrix, and categorized token consumption list (--viz-1..--viz-6, surface, border, typography, motion tokens).

§14

Developer notes

Always

Defines framework integration patterns, reactive data binding, export capabilities (CSV, SVG, PNG), automated chart testing recipes, and specification freeze status.

Must answer

Framework integration code sample with typed data input; real-time data streaming subscription pattern (buffering incoming WebSocket points without re-rendering the entire SVG tree); data export hooks (exportCSV(), exportPNG()); unit and visual regression testing assertions (verifying scale domains, ARIA tree validity, keyboard arrow navigation, contrast ratios); and open/closed governance item registry with freeze date.

Shape

TypeScript integration example, data stream hook snippet, test assertion list, and status/open-item registry table.
