Composite components

Composite index

Every composite here is a standardized assembly of existing Core Components that carries meaning the parts do not carry alone, and each specification documents only what the composition adds — see the composite spec standard for the section set and the include/omit tests. The one recurring theme so far: every composite here coordinates a control size its children could not agree on by themselves. FileUpload is the first that also coordinates a status — whether the set it holds is finished — which is what its surface's Save button depends on.

Toolbar

Box, Divider · Button, IconButton, ButtonGroup, SegmentedControl, Menu
  • Owns the role="toolbar" boundary and name, one tab stop with a coordinated arrow contract, the visible/overflowed relationship, one control size, and an aggregate disabled state.
  • Refuses navigation, unrelated controls, and use as a horizontal alignment device.

SearchField

Box, Text · Input, Icon, IconButton, Button
  • Owns the query contract (value/onChange, clearing as an ordinary value change), search semantics, clear and submit as permanently separate actions, and one size across field, clear and submit.
  • Refuses results, suggestions, filters and result counts — suggestions are Autocomplete's contract, not a feature of this one.

SplitButton

Box · Button, IconButton, Menu, MenuList, Icon
  • Owns the relationship between a default action and its alternatives: which action is primary, that the disclosure never invokes it, one aggregate disabled state, two distinct accessible purposes, matched geometry with a single seam, and the menu's ownership by the cap.
  • Refuses space-saving, unrelated commands in the menu, use where no action is clearly primary, and standing in for ButtonGroup when actions are peers.

DateRangePicker

Box, Text · DatePicker, Icon · optional Field
  • Owns one range value ([start, end]), ordering, cross-field validation and which endpoint a failure implicates, per-endpoint accessible identity and validation association, bounds on each endpoint derived from the other, and an arrangement that may stack without reordering time.
  • Refuses domain rules (duration caps, blackout periods), open-ended intervals, presets, and swapping the user's entries — correct in DatePicker range's one panel, wrong across two named fields.

DateTimePicker

Box, Text · DatePicker, TimeField, Icon · optional Field
  • Owns assembly and disassembly of one moment — a UTC instant edited on the Site's clock, or an explicitly floating 'YYYY-MM-DDTHH:mm' when there is no zone — plus explicitly defined partial behaviour (nothing inferred), the two daylight-saving states that only exist once conversion is real, combined validation against Site-clock bounds compared at the precision given, per-half identity and validation association, and reflow that never reorders date and time.
  • Refuses the reader's clock (the zone comes from the record's Site, as an IANA name — an abbreviation is refused), silently accepting a clock time that does not exist, inferred halves, and domain rules.

FileUpload

Field · FileDropzone, FileItem
  • Owns the set: one aggregate status derived from every file's own state (idle / busy / failed / invalid) and therefore whether the record may be saved, one field identity and one validation message across several controls, rejection codes turned into sentences once, focus after a removal, an aggregate disabled state, and one size down a single column.
  • Refuses the queue and the transport (both stay with the surface, as they do on both parts), a set-level spinner in place of per-file bars, reordering rows by state, two dropzones in one set, and the table form of a large attachment list.

SortableCollection

IconButtonPromoted from the direct-manipulation-of-order pattern · unfrozen, API open
  • Owns the grab as one object carrying identity and origin index, a modal keyboard grab whose arrows move the proposal rather than the focus, per-candidate-position legality declared as a reason rather than a boolean and evaluated by one function from three call sites, the insertion indicator, the position text on every row, one control rhythm across handle and steppers, an origin index re-derived when the collection changes underneath a live grab, and every announcement of a grab, proposal, refusal, abandon and result.
  • Refuses the commit entirely — it never reorders items, holds no optimism and computes no rollback — plus items keyed by index, a canDrop that answers false, a handle that grabs and refuses everywhere, a drag as the only route to an off-screen destination, reordering offered under a foreign sort, two live regions, and transfer between two collections, whose commit spans both and stays a pattern.
