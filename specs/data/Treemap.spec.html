Treemap Component Specification

Standard Specification Document for Hierarchical Part-to-Whole Area Encodings
● status: frozen 9 Sep 2026 · 0 open items

§01 Purpose & Analytical Intent

The Treemap component is designed to compare quantitative magnitude within a multi-level hierarchy while rigorously preserving containment and parent-child membership relationships. It packs space efficiently by dividing a bounding rectangle into nested sub-rectangles whose areas correspond directly to positive quantitative values.

  • Primary analytical question: "What proportion of the whole belongs to each branch and leaf within the operational hierarchy?"
  • Contextual enterprise scenario: Shop-floor energy distribution (Plant → Shop → Equipment), raw material scrap cost loss, and asset maintenance budget allocations at Suryodaya Autocomp Ltd (Chakan plant PL-04, Pune).

§02 Data Model & Transformation

Input data is defined as a hierarchical tree structure where leaf nodes possess non-negative quantitative values. Branch container values are derived recursively via bottom-up summation in rollupHierarchy(): 

// Formal Node Hierarchy Model
interface TreemapNode {
  id: string;              // Unique node identifier
  label: string;           // Display name (e.g. "Press Shop")
  category?: string;       // Color categorization key
  value?: number;          // Leaf quantitative metric (>= 0)
  children?: TreemapNode[]; // Nested branch child nodes
}

// Rollup Formula
Value(Branch) = Sum(Value(Child_i)) for all Child_i in Branch.children

Negative values are mathematically invalid in area part-to-whole encodings and are clamped to 0.

§04 Component Composition & Layer Stacking

The Treemap utilizes a strict 6-layer z-index structure:

  1. Layer 0 (Canvas): Outer SVG background canvas and pattern definition dictionary.
  2. Layer 10 (Branch Containers): Sunken background rectangles (#f8fafc) and top header banners (#e2e8f0) for branch grouping.
  3. Layer 20 (Leaf Tiles): Base categorical color fill rectangles with 3px border radius.
  4. Layer 25 (Hatch Patterns): Transparent SVG monochrome line/dot hatch pattern textures for WCAG 1.4.1 non-color differentiation.
  5. Layer 30 (Labels & Value Text): High-contrast white typography with text-shadow: 0 1px 2px rgba(0,0,0,0.7).
  6. Layer 50 (Interactive Overlays): Floating tooltip portal and accessible table modal (Alt+F11).

§06 States & Interactions

  • Default State: All visible nodes rendered within plot bounds with stable sorting (descending value).
  • Hover State: Hovered leaf retains 100% opacity; non-hovered leaves dim slightly to 75% opacity; floating tooltip displays lineage, value, and parent/root share percentages.
  • Drilled State: Clicking a branch or pressing Enter zooms into the subtree. The breadcrumb trail updates dynamically (e.g., Plant PL-04 › Press Shop › Line 01).
  • Focused State: White dashed focus ring (stroke-dasharray: 3 2) rendered over focused rectangle.

§07 Layout Algorithms & Geometry

The default Squarified Treemap algorithm (Bruls, Huizing, van Wijk, 2000) subdivides rectangular space into rows of tiles such that the maximum aspect ratio of each rectangle is minimized towards 1.0: 

// Worst Aspect Ratio Formulation
AspectRatio(r, s, S) = max((s^2 * r) / S^2, S^2 / (s^2 * r))
where:
  s = length of the shortest side of the remaining bounding box
  S = cumulative area sum of the items in the current proposed row
  r = individual area of item under evaluation

Items are presorted descending by magnitude prior to partitioning to guarantee layout determinism across routine data polling.

§08 Labeling, Clipping & Density Rules

To prevent unreadable spatial clutter, internal text labels adhere to strict adaptive thresholds:

  • Primary Label: Rendered if width ≥ 40px and height ≥ 24px. Truncated with ellipsis (…) if text width exceeds cell boundary.
  • Metric Value: Rendered if width ≥ 60px and height ≥ 40px.
  • Percentage Share: Rendered if width ≥ 75px and height ≥ 56px.
  • Micro-Cells (w < 40px or h < 24px): Text is suppressed; metrics remain accessible via hover tooltip and Alt+F11 data table.

§09 Responsive & Breakpoint Behavior

  • Fluid Resizing: Recomputes rectangular partitions when width/height change while maintaining relative aspect ratios.
  • Small Screens (< 480px): Automatic depth restriction (maxDepth = 2) to prevent micro-cell fragmentation.

§10 Accessibility & Dual-Encoding (WCAG 2.2 AA / AAA)

  • WCAG 1.4.1 (Non-Color Differentiation): Every category is differentiated by both a distinct hex hue and an SVG hatch pattern texture (stripes, dots, crosshatch).
  • WCAG 2.1.1 (Keyboard Operability): Full 2D navigation (←/→/↑/↓), drilldown (Enter/Space), drill up (Backspace/Esc), and start/end (Home/End).
  • WCAG 4.1.3 (Status Messages): Dynamic aria-live="polite" announcements upon selection and navigation.
  • Non-Spatial Modal Alternative: Alt+F11 accessible hierarchical data table.

§11 Color Palettes, Tokens & Themes

Adheres strictly to Meridian design tokens: --viz-1 through --viz-6, --surface-card, --surface-sunken, --border-subtle, --text-primary, and --text-secondary.

§12 Motion & Transitions

Tile opacity and border strokes transition at 150ms ease on hover. Zoom transitions preserve spatial continuity without disorientation.

§13 Anti-Patterns & Error Handling

  • ❌ Do NOT use for high-precision leaf comparisons: Use horizontal BarChart when exact reading of small differences is required.
  • ❌ Do NOT permit negative values: Area encodings cannot represent negative quantities.
  • ❌ Do NOT overload depth: Avoid rendering >3 levels simultaneously without drilldown containers.

import React from 'react';
import { Treemap } from '@meridian/design-system';

const plantHierarchy = {
  label: 'Chakan Plant (PL-04)',
  children: [
    {
      label: 'Press Shop',
      category: 'Press Shop',
      children: [
        { label: '800T Transfer Press', value: 1420 },
        { label: '400T Tandem Press', value: 980 }
      ]
    },
    {
      label: 'Welding Cell',
      category: 'Welding Cell',
      children: [
        { label: 'Robotic Spot Welders', value: 890 }
      ]
    }
  ]
};

export function Dashboard() {
  return (
    <Treemap
      data={plantHierarchy}
      unit="kWh"
      title="Plant Power Distribution"

      height={420}

    />
  );
}
