§01 Purpose & Relational Topology Intent

The NetworkDiagram component visualizes arbitrary relational structures, connectivity patterns, clusters, and central hubs where relationships cannot be simplified to strict single-parent trees or sequential stages. It optimizes for structural discovery, community detection, and topological relationship exploration.

  • Primary analytical questions: "Which nodes act as central hubs?", "What clusters or communication meshes exist?", "Which entities are directly/indirectly connected to a selected node?"
  • Contextual enterprise scenario: Industrial IoT sensor mesh connectivity, Tier-1 automotive supply chain networks, and cross-functional maintenance dependencies at Suryodaya Autocomp Ltd (Chakan plant PL-04, Pune).

§02 Data Model & Graph Topology

Data is structured as a general graph $G = (V, E)$ consisting of entity vertices (nodes) and relational edges (links): 

interface NetworkNode {
  id: string;              // Unique node ID
  label: string;           // Display name (e.g. "MES Gateway")
  category?: string;       // Categorical clustering group
  size?: number;           // Degree weight or relative importance
}

interface NetworkLink {
  source: string;          // Source node ID
  target: string;          // Target node ID
  weight?: number;         // Edge strength / bandwidth (> 0)
  directed?: boolean;      // True for directed arrows
  label?: string;          // Relationship description
}

§03 Visual Encoding & Network Anatomy

Visual Channel Data Attribute Design & Scaling Rule
Node Position (X, Y) Topological Closeness Positions computed via deterministic force-directed physics (repulsion + attraction) or circular ring. Fully draggable & stretchable.
Node Size (Radius) Importance / Degree Centrality Radius scales from 8px to 26px based on node degree and weight.
Edge Stroke Width Relational Weight / Traffic Scales from 1px to 6px proportional to sqrt(weight).
Arrowheads Directional Relationship SVG marker arrowheads placed at target node boundary.

§04 Component Composition & Layer Stacking

  1. Layer 0 (Canvas): SVG background viewport with pan & zoom transform matrix and arrowhead marker definitions.
  2. Layer 10 (Relational Edges): Connecting straight/curved link lines with weight-proportional strokes.
  3. Layer 20 (Node Marks): Primary circular surfaces with category color fills and white border strokes.
  4. Layer 25 (Geometric Symbols): Inner geometric shape glyphs (circle, square, diamond, triangle) for WCAG 1.4.1 non-color differentiation.
  5. Layer 30 (Node Typography): Text labels with background stroke halos.
  6. Layer 50 (Inspection Overlays): Floating tooltip portal and accessible relationship table modal (Alt+F11).

§05 Properties, Props & Configuration

Prop Type Default Description
nodes NetworkNode[] Required Array of graph vertices with unique IDs and labels.
links NetworkLink[] Required Array of relational edges between nodes.
draggableNodes boolean true Allows users to click and drag individual nodes to stretch and de-clutter clusters.
initialSpread number 1.0 Global spacing/repulsion multiplier (0.6x - 2.2x) to untangle dense networks.
layout 'force' | 'circular' 'force' Graph layout algorithm.
directed boolean true Renders directional arrowhead markers on edges.
searchable boolean true Includes search filter input to quickly find and highlight nodes.
zoomable boolean true Enables viewport pan and zoom controls.

§06 States & Interactions (De-Cluttering & Stretching)

Dense Network De-Cluttering Mechanisms:
1. Interactive Node Stretching: Users can click and drag any node to manual coordinates. Connected edges stretch dynamically without restarting chaotic simulation.
2. Dynamic Stretch/Spread Slider: Adjusts the global spring distance ($d \times \text{multiplier}$) and Coulomb repulsion ($k_r \times \text{multiplier}^2$) from 0.6x to 2.2x.
3. 1-Hop Neighborhood Isolation: Dims unrelated topology to 15% opacity on hover/selection.

§07 Layout Algorithms & Geometry

The force layout runs 120 deterministic iterations using simulated annealing cooling: 

// 1. Coulomb Repulsion (Scales with Spread Multiplier)
F_repulsion(u, v) = (k_repulsion * spread^2) / dist(u, v)^2

// 2. Hooke Spring Attraction (Rest length scales with Spread Multiplier)
F_attraction(u, v) = (dist(u, v) - (restLength * spread)) * k_spring * sqrt(weight)

// 3. Simulated Annealing Cooling
Temperature(t + 1) = Temperature(t) * 0.96

§08 Labeling, Collision & Density Rules

Labels are rendered beneath each node with a high-contrast 3px white stroke halo (paint-order: stroke) to maintain legibility over crossing edges.

§09 Responsive & Viewport Scaling

  • Pan & Zoom Viewport: Allows free exploration of dense clusters without spatial clipping.
  • Density Decimation: Low-weight edges (< 0.5) can be filtered on small screens.

§10 Accessibility & Dual-Encoding (WCAG 2.2 AA / AAA)

  • WCAG 1.4.1 (Non-Color Differentiation): Dual-encoded with unique geometric symbols (circle, square, diamond, triangle) and category colors.
  • Searchable Navigation: Real-time search filter eliminates spatial traversal barriers for screen reader users.
  • Non-Spatial Modal Alternative: Alt+F11 accessible adjacency table listing degree and neighbor connections.

§11 Color Palettes, Tokens & Themes

Adheres to Meridian tokens: --viz-1 through --viz-6, --surface-card, --border-subtle, and --action-solid.

§12 Motion & Transitions

Edge opacity and node selection rings transition at 150ms ease. The force simulation settles deterministically on mount without continuous layout jitter.

§13 Anti-Patterns & Error Handling

  • ❌ Do NOT use for hierarchical taxonomies: Use TreeDiagram for single-parent trees.
  • ❌ Do NOT use for quantitative flow splits: Use SankeyDiagram when volume conservation is key.

import React from 'react';

const meshData = {

      draggableNodes={true}
      initialSpread={1.2}
      title="Shop-Floor IoT Mesh"
      width={760}
      height={440}
    />
  );
}
