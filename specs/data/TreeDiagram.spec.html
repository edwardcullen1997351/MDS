Tree Diagram Component Specification

Standard Specification Document for Explicit Parent-Child Topology & Lineage
● status: frozen 9 Sep 2026 · 0 open items

§01 Purpose & Structural Topology Intent

The TreeDiagram component communicates explicit parent-child topology, ancestry, branching structure, and hierarchical lineage. Unlike space-filling area charts (e.g. Treemap), its analytical grammar optimizes for structural comprehension, path traversal, and progressive disclosure of tree depths.

  • Primary analytical questions: "What is the upstream/downstream lineage of this asset?", "Which sub-assemblies compose this Bill of Materials?", "How does operational reporting escalate across shop leadership?"
  • Contextual enterprise scenario: Shop-floor equipment topology, EV chassis engineering BOMs, and shift supervision matrices at Suryodaya Autocomp Ltd (Chakan plant PL-04, Pune).

§02 Data Model & Transformation

Data is modeled as a rooted acyclic tree with unique node IDs, labels, operational metadata (status, code, role), and optional child arrays: 

// Hierarchy Node Model
interface TreeNode {
  id: string;              // Unique node ID
  label: string;           // Display title (e.g. "800T Transfer Press")
  code?: string;           // Asset code or Part number (e.g. "PS-800T-01")
  role?: string;           // Functional designation
  status?: 'operational' | 'maintenance' | 'alarm' | 'idle';
  children?: TreeNode[];   // Ordered array of child nodes
}

Multi-parent cycles or detached subgraphs are disallowed in pure tree diagrams.

§03 Visual Encoding & Anatomy

Visual Channel Data Attribute Design & Layout Rule
Spatial Position (X, Y) Hierarchy Depth & Sibling Index Depth along major axis (X for horizontal, Y for vertical); sibling spacing along minor axis.
Connecting Edges (Links) Parent-Child Lineage Smooth cubic bezier curves, orthogonal step lines, or straight vectors. Highlighted in blue (#2563eb) on active path.
Node Cards Entity Representation Surfaces with primary title, code/role caption, status dot, and accent stripe.
Expansion Badges Subtree Fold State Circular badge with + (collapsed) or − (expanded) showing branch interactivity.

§04 Component Composition & Layer Stacking

  1. Layer 0 (Canvas): SVG background viewport with pan & zoom transform matrix.
  2. Layer 10 (Hierarchy Links): Background SVG paths connecting parent anchor to child anchor.
  3. Layer 20 (Node Cards): Rectangular card surfaces with 6px border radius, border stroke, and drop shadow.
  4. Layer 30 (Node Content): Text labels, subtitle codes, status indicators, and focus outlines.
  5. Layer 40 (Expansion Badges): Interactive circular toggle badges positioned along edge intersection points.
  6. Layer 50 (Modal Overlays): Accessible hierarchical tree table modal (Alt+F11).

§05 Properties, Props & Configuration

Prop Type Default Description
data TreeNode Required Root hierarchical tree node object.
orientation 'horizontal' | 'vertical' 'horizontal' Tree growth direction. Horizontal (Left-to-Right) or Vertical (Top-to-Bottom).
linkStyle 'smooth' | 'step' | 'straight' 'smooth' Curve geometry for connecting edges.
collapsible boolean true Enables interactive expanding and collapsing of subtrees.
zoomable boolean true Enables viewport pan and zoom toolbar with reset controls.

§06 States & Interactions

  • Expanded State: All children of the branch are measured and laid out. Link lines connect parent to each child.
  • Collapsed State: Subtree nodes are hidden; circular badge displays + indicator.
  • Ancestor Path Highlight: Hovering or selecting any node highlights the exact path of links and ancestor cards up to the root.
  • Pan & Zoom State: Viewport supports continuous panning via mouse drag and zoom in/out with auto-fit reset.

§07 Layout Algorithms & Geometry

The computeTreeTopology() engine recursively measures subtree bounding breadths and centers parent nodes along the span of their visible children: 

// Centered Parent Coordinate Formulation
Breadth(Parent) = Sum(Breadth(Child_i)) for all Child_i in Parent.children
Position(Parent) = SiblingOffset + (Breadth(Parent) - NodeSize) / 2

§08 Labeling, Cards & Density Rules

Labels are contained inside structured cards with fixed dimensions (default 160x54px). Titles exceeding 18 characters are truncated with an ellipsis. Status dots provide immediate semantic awareness.

§09 Responsive & Viewport Scaling

  • Pan & Zoom Viewport: Allows navigation across extensive trees without clipping.
  • Initial Collapsing: Deep hierarchies (>3 levels) can default to collapsed state for clean initial rendering.

§10 Accessibility & Dual-Encoding (WCAG 2.2 AA / AAA)

  • Semantic Roles: role="tree" and role="treeitem" with aria-expanded on branch nodes.
  • Keyboard Navigation: Full 2D traversal (←/→/↑/↓), toggle expansion with Enter / Space, and Home/End.
  • Live Screen Reader Announcements: aria-live="polite" announces expansion and selection states.
  • Non-Spatial Modal Alternative: Alt+F11 accessible hierarchical data table.

§11 Color Palettes, Tokens & Themes

Adheres to Meridian status tokens: --status-success-solid (operational), --status-warning-solid (derated/maintenance), --status-critical-solid (alarm/stoppage), and --action-solid (path selection).

§12 Motion & Transitions

Link paths and node cards transition at 150ms ease. Fully respects prefers-reduced-motion: reduce.

§13 Anti-Patterns & Error Handling

  • ❌ Do NOT use for arbitrary graph topologies: Tree diagrams require a strict single-parent hierarchy.
  • ❌ Do NOT encode quantitative share via area: Use Treemap for magnitude comparison.
